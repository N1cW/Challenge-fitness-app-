# Импульс — платформа спортивных челленджей

Курсовой проект по дисциплине «Разработка клиент-серверных приложений». Веб-клиент позволяет искать челленджи, регистрироваться, отмечать результаты и следить за таблицей участников. Организатор создаёт и редактирует свои челленджи; администратор может изменять любые. События участия и прогресса передаются подписанным клиентам через WebSocket.

## Архитектура

| Уровень | Реализация | Обязанности |
| --- | --- | --- |
| Клиент | HTML, CSS, JavaScript; Nginx в Compose | интерфейс, формы, навигация, запросы HTTP и WebSocket |
| Сервер | Python, FastAPI, SQLAlchemy | API, валидация, JWT, роли, бизнес-правила |
| Данные | PostgreSQL в Compose; SQLite для локальной разработки/тестов | пользователи, челленджи, участие, записи прогресса |

Исходники находятся в `frontend/` и `backend/`, диаграммы — в `docs/diagrams/`, план и фактические проверки — в `work/`.

## Быстрый запуск через Docker Compose

Требуются Docker Engine и Docker Compose. Скопируйте `.env.example` в `.env`, замените оба значения паролей/ключей случайными длинными строками и выполните:

```powershell
docker compose up --build -d
docker compose ps
```

Интерфейс: http://localhost:8080/ (или порт `WEB_PORT`). Документация OpenAPI: http://localhost:8080/docs. Проверка здоровья: http://localhost:8080/api/health.

Чтобы создать демонстрационные данные, задайте свой пароль только в терминале и выполните:

```powershell
$env:SEED_PASSWORD='ВашТестовыйПарольНеКороче10Символов'
docker compose exec -e APP_ENV=development -e SEED_PASSWORD=$env:SEED_PASSWORD backend python -m app.seed
```

Демонстрационные адреса: `admin@example.com`, `organizer@example.com`, `user@example.com`. Для всех используется указанный вами `SEED_PASSWORD`; он не хранится в репозитории. Повторный запуск seed не дублирует пользователей или челленджи.

## Запуск без Docker

Из папки `backend/` создайте Python 3.12 окружение, установите `requirements-dev.txt`, задайте `APP_ENV=development` и `SEED_PASSWORD`, затем:

```powershell
python -m app.seed
python -m uvicorn app.main:app --reload --port 8000
```

Откройте http://localhost:8000/; локально FastAPI раздаёт те же статические файлы, что Nginx в Compose. По умолчанию данные записываются в `challenge.db` (SQLite, файл исключён из Git). Для PostgreSQL задайте `DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/DB`.

## API

| Метод | Путь | Доступ | Назначение |
| --- | --- | --- | --- |
| POST | `/api/auth/register`, `/api/auth/login` | все | регистрация/вход, получение JWT |
| GET | `/api/me` | пользователь | профиль и роль |
| GET | `/api/challenges`, `/api/challenges/{id}` | все | список, фильтрация и карточка |
| POST | `/api/challenges` | организатор, администратор | создать челлендж |
| PATCH, DELETE | `/api/challenges/{id}` | автор или администратор | изменить/удалить |
| POST, DELETE | `/api/challenges/{id}/join` | пользователь | участие/выход |
| POST, GET | `/api/challenges/{id}/progress` | участник | добавить/посмотреть свой прогресс |
| GET | `/api/challenges/{id}/leaderboard` | все | таблица результатов |
| WebSocket | `/ws/challenges/{id}` | пользователь | события по челленджу |

После открытия WebSocket клиент первым сообщением отправляет JSON `{"token":"<JWT>"}`. Сервер отвечает `{"event":"ready","challenge_id":...}` и далее сообщает об изменениях. Токен не включается в URL. Подробные схемы запросов и ответов генерируются FastAPI на `/docs`.

## Тестирование

Из папки `backend/`:

```powershell
python -m pytest -q
```

Тесты покрывают регистрацию, отрицательные сценарии авторизации и ролей, CRUD, участие, прогресс, WebSocket и генерацию граничных входных данных Hypothesis. Фактические результаты каждого запуска записываются в `work/VERIFICATION.md`.

## Безопасность и ограничения

Пароли хешируются PBKDF2-HMAC-SHA256 с индивидуальной солью; JWT подписываются ключом из окружения. В релизной среде ключ короче 32 символов не принимается. Регистрация всегда выдаёт роль `user`; роли организатора и администратора назначаются только операционно через seed или администрирование БД. Токен в браузере хранится в `sessionStorage`; сервер не журналирует его. Перед публичным развёртыванием нужны HTTPS/WSS, управление секретами, резервное копирование БД и более строгая политика загрузки ресурсов.

Вместо миграций текущий прототип создаёт отсутствующие таблицы при старте (`Base.metadata.create_all`). Для изменения схемы без потери данных в развитии проекта потребуется Alembic. Облачное развёртывание выполняется только при наличии выбранной платформы и доступа к ней; наличие Compose само по себе не подтверждает развёртывание в облаке.

## Развёртывание в Render

Файл `render.yaml` описывает production-окружение: Python-сервис, управляемую PostgreSQL, проверку `/api/health` и переменные окружения. `SECRET_KEY` генерируется Render, а строка подключения берётся из созданной базы; секреты в репозитории не хранятся.

1. В Render откройте **New → Blueprint** и подключите репозиторий.
2. Выберите `render.yaml` в корне. При создании Blueprint задайте секрет `SEED_PASSWORD` длиной не менее 10 символов.
3. Подтвердите создание ресурсов. После успешной проверки здоровья откройте выданный адрес `onrender.com`.

При первом развёртывании создаются демонстрационные учётные записи с общим паролем из `SEED_PASSWORD`:

| Учётная запись | Роль | Проверяемый вариант использования |
| --- | --- | --- |
| `user@example.com` | `user` | вступление в челлендж, запись прогресса, просмотр результата |
| `organizer@example.com` | `organizer` | создание и изменение собственных челленджей |
| `admin@example.com` | `admin` | изменение любого челленджа и проверка полного доступа |

Пароль не записывается в репозиторий. Команда инициализации повторяема: она не создаёт дубликаты пользователей или челленджей.

Один репозиторий используется для всех развёртываний. Локальная разработка, staging и production отличаются переменными окружения и активной ревизией, поэтому отдельные ветки с копиями конфигурации для соблюдения Twelve-Factor App не требуются.
